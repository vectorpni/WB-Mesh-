# План GIS-интеграции

1. Сохранить 24 ПВЗ / 18 Mesh и 3 хаба V8; сопоставить их с 16 ПВЗ и 3 хабами Core V2 (`app.py:1024–1053`). Не выдавать случайно сгенерированные координаты за адреса WB.
2. Добавить WGS84-координаты с происхождением/статусом «демонстрационные» в единый серверный справочник. Проверить допустимые диапазоны и географическую принадлежность города.
3. Встроить Leaflet 1.9.4 в MCS экран V8. Маркеры, ограничения, остатки и выбранный маршрут получать из серверного состояния. Сохранить атрибуцию OSM; проверить CDN и лицензию до локального включения библиотек.
4. Адаптер OSRM: конфигурируемый URL, одиночный Route, Trip только для порядка остановок, Table для матрицы, steps для манёвров; явные таймауты, кэш, лимиты, отказ. Публичный OSRM использовать только для ограниченных демонстрационных запросов.
5. Модель `road_live / road_cached / estimate / unavailable`; приближение пунктиром, без навигационных манёвров. М1 и совпадающие координаты — нулевое движение без искусственной линии.
6. Сверить дорожную дистанцию и время с экономикой как отдельный сценарный режим, не менять контроль ТЗ 100/92,96 ₽.

Проверка: одна и несколько остановок, разрыв связи, короткий маршрут, совпадение координат, чужой город, некорректная GeoJSON, отклонённый OSRM, отсутствие тайлов, мобильный экран. Выполнение пока не началось.

## Уточнение части 3/5, блока 3/10 — геодезия и дорожный граф

- Единый формат точек — WGS84: широта `[-90,90]`, долгота `[-180,180]`, конечные числа, явный порядок полей. Для формулы гаверсинусов перевести градусы в радианы и ограничить вычисленное `a` диапазоном `[0,1]` перед корнями/`atan2`, чтобы ошибка округления не создала `NaN`. `haversine_km()` Core V2 — исходная реализация для проверки; корректность крайних случаев ещё не доказана динамическими тестами.
- `haversine_km()` возвращает геодезическую предварительную оценку. Дорожное расстояние и время получаются только из ответа дорожного графа OSRM либо из валидного сохранённого ответа с метаданными происхождения, времени и версии. Не применять коэффициент fallback как доказанное расстояние по дорогам.
- Route — направленный маршрут и его GeoJSON/манёвры; Trip — порядок остановок без обещания решения CVRP; Table — направленная матрица расстояний и времени; Nearest — привязка валидной точки к дорожной сети по необходимости с контролем максимального смещения. Результат обратного направления рассчитывать отдельно: односторонние улицы могут сделать `A→B` и `B→A` разными. Проверять `code`, наличие маршрута, порядок точек, конечность/неотрицательность чисел и геометрию ответа.
- Источник геометрии в серверном ответе: `road_live`, `road_cached`, `estimate`, `unavailable`. Кэш содержит исходные точки, профиль, источник, время расчёта и применимость; устаревший или неподходящий кэш нельзя молча объявлять текущим. `estimate` отображается пунктиром и без выдуманных улиц/поворотов; `unavailable` — понятное отсутствие маршрута. Для M1 и совпадающих источника/назначения нет искусственной петли.
- Маркеры синтетических ПВЗ должны иметь заметную отметку «демонстрационный объект» и происхождение координат. Leaflet, OSM и OSRM не превращают эти точки в подтверждённую инфраструктуру WB. Сохранять OSM attribution.

Будущие проверки: нечисловые/вне диапазона/совпадающие/почти совпадающие/антиподальные координаты; маршрут по односторонней дороге в обоих направлениях; Route/Trip/Table/Nearest и неполный ответ; смещение Nearest; живой/кэшированный/оценочный/недоступный режим; отсутствие манёвров при fallback. Проверки пока не выполнялись.
