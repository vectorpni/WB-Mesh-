# Транспортная математика — подготовительный контракт

Статус: часть 3/5, блок 6/10. **Только документирование будущей реализации.** Действующую финансовую модель V8 и её контроль `100/92,96 ₽` сохранять; расширенная географическая себестоимость — отдельный режим. Никакие расчётные исходники V10 этим документом не изменены.

## Контроль ТЗ

При целых `n>0`, `k≥1`, `t≥0`:

`C_run = 480 + 8n + 40(k−1) + 6t` ₽; `C_unit = C_run/n` ₽/отправление.

Для `n=40,k=1,t=0`: `480+8×40=800 ₽`, `800/40=20 ₽`. При альтернативе `24 ₽/отправление` экономия по **транспорту** на единицу равна `24−C_unit`. Равенство `24 = 8 + [480+40(k−1)+6t]/n` даёт `n_eq=[480+40(k−1)+6t]/(24−8)` и минимальную строго выгодную целую партию `floor(n_eq)+1`. В базовом случае `n_eq=480/16=30`, значит при `n=30` экономия нулевая, с `n=31` положительная. Это не порог полной цепочки: хранение, сортировка, выплаты, риск, IT и другие применимые статьи требуют собственного расчёта согласно `FINANCIAL_MODEL.md` и ТЗ.

Не делить при `n=0`. Для общего `C_alternative` при `C_alternative≤8` положительного порога при неотрицательных фиксированных расходах нет; формулу с нулевым знаменателем не вычислять. Отрицательные `n,t`, `k<1`, нецелые отправления/остановки, нечисловые и бесконечные входы отклонять. Пограничное равенство не называть экономией. Денежные суммы хранить/суммировать в копейках; деление на число отправлений и округление показывать по принятому правилу, не округляя до сравнения прибыльности.

## Отдельный эксплуатационный сценарий

Пусть `D` — подтверждённый дорожный пробег в км, `Q` — л/100 км, `P_fuel` — ₽/л, `Rate_amortization` — ₽/км, `T_work` — часы труда, `Rate_driver` — ₽/час. Тогда `Fuel=D×Q/100` л; `C_fuel=Fuel×P_fuel`; `C_amortization=D×Rate_amortization`; `C_driver=T_work×Rate_driver`. Обслуживание и другие статьи добавлять только при известных сценарных ставках с единицами измерения и источником параметров.

Сценарный расчёт должен показывать перечень включённых статей. Не прибавлять топливо, амортизацию или труд поверх `480`/`8n`/`40(k−1)`/`6t`, пока не доказано, что соответствующая статья отсутствует в контрольной ставке. Если такой разбор первоисточника невозможен, считать эксплуатационную модель самостоятельной альтернативой, а не «улучшенной» контрольной цифрой. Для общего рейса фиксированные затраты учитывать один раз; при попутном заказе отдельно показывать `ΔC=C_new−C_existing`.

## Будущие проверки

| Сценарий | Ожидаемый результат |
|---|---|
| `n=40,k=1,t=0` | 800 ₽ за рейс, 20 ₽/отправление |
| `n=30` и альтернатива 24 ₽ | Транспортное равенство, 0 ₽ экономии |
| `n=31` и альтернатива 24 ₽ | Строго положительная транспортная экономия |
| `n=0`, `C_alternative=8` | Понятный отказ без деления на ноль |
| Дополнительная остановка или простой | Порог пересчитан по тем же исходным параметрам |
| Эксплуатационный сценарий | Единицы и ставки видны; нет двойной записи общей стоимости рейса |
