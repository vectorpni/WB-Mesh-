# Четыре модели маршрутизации — подготовительный контракт

Статус: часть 3/5, блок 4/10. **Документ проектирования, не свидетельство работающей интеграции.** Сохранять существующий выбор M1/M2/C1/C2 основного V8 и контрольную экономику ТЗ. Географию Core V2 использовать после проверки; его тарифы не переносить автоматически.

| Модель | Условие допустимости | Физическая цепочка | Автомобильное движение |
|---|---|---|---|
| M1 | Подтверждённый доступный товар выбранного продавца уже в конечном ПВЗ Б | Резерв → сборка → выдача | Нет: 0 км, 0 минут, рейс не создаётся |
| M2 | Товар в другом активном Mesh-ПВЗ того же города, ограничения и запас допускают передачу | Источник А → ПВЗ Б | Дорожный маршрут по направлению А→Б, со статусом происхождения геометрии |
| C1 | Городской товар и предусмотренные ТЗ городские узлы/операции доступны | Источник → предусмотренные ТЗ городские узлы → ПВЗ Б | Отдельные допустимые участки, без пропуска необходимых операций |
| C2 | Междугороднее происхождение подтверждено; предусмотренные ТЗ хабы и магистраль доступны | Источник → отправляющий хаб → магистраль → принимающий хаб → ПВЗ Б, согласно ТЗ | Участки рассчитываются отдельно; нельзя заменить городским M2/C1 из-за близости на карте |

Точная структура C1/C2, допустимые узлы, время операций и тарифы должны быть сверены с оригинальным ТЗ и утверждённой презентацией при реализации. Таблица не добавляет вымышленные объекты или тарифы. Подтверждённый локальный источник может породить отдельного городского кандидата, но это не превращает междугородний кандидат в городской.

## Кандидат и выбор MCS

Для каждого участка хранить исходный и конечный узлы, направление, километры, время движения, время операций и ожидания, стоимость по единому тарифному модулю, состояние и количество товара до/после, источник геометрии (`road_live`, `road_cached`, `estimate`, `unavailable`) и причину недопуска. Проверять продавца, партии, доступный остаток после резервов, карантин/брак, статус и часы узлов, вместимость узлов и транспорта, SLA и экономику WB, ПВЗ, продавца и покупателя.

Сначала сформировать все физически допустимые кандидаты из **подтверждённых** источников. Затем применить финансовые и временные ограничения четырёх участников, сравнить оставшиеся по заданной цели и детерминированному правилу равенства. Ближайшая точка не определяет победителя сама по себе. Журнал MCS сохраняет формулы, тарифную версию, входной снимок, кандидатов, ограничения, причины отказа и выбранный вариант. Если вариантов нет, вернуть конкретные причины по кандидатам и не создавать заказ/резерв/рейс.

M1 имеет нулевое **автомобильное** время, но может включать проверенные складские и операционные длительности. Для M2/C1/C2 приблизительная линия при отказе OSRM не выдаётся за дорожную навигацию; политика допустимости оценки должна быть явно определена, а обещанный срок не представляется подтверждённым дорожным временем.

## Будущие проверки

| Случай | Ожидаемое поведение |
|---|---|
| Товар в ПВЗ Б | M1 без петли, автомобиля и рейса; операционное время отдельно |
| Другой Mesh-ПВЗ того же города | M2 с проверенным источником и направленным дорожным участком |
| Межгород, нет локального запаса | C2 остаётся межгородом либо даёт отказ; городская подмена запрещена |
| Локальный запас подтверждён при межгороде | Городской кандидат формируется отдельно; обе альтернативы сравниваются |
| Ближайший источник дороже или недоступен | Выбран допустимый экономически выгодный вариант с объяснением |
| Нет запаса, закрытый узел, переполнение или отказ по четырём сторонам | Конкретная причина; нет заказа, резерва и рейса |

Проверки запланированы, **не выполнены**. Подтверждённые статическим анализом дефекты Core V2 перечислены в `CORE_V2_P0_FIXES.md` (в частности, P0-01, P0-03, P0-08, P0-11, P0-19).
