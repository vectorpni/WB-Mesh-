# Навигация Core V2: что сохранять и что исправить

Сохранять структуру OSRM Route/Trip запроса (`app.py:380–399`), реальную GeoJSON-линию, расстояние и длительность (`401–419`), `haversine_km()` только как оценку (`296–301`).

Исправить до показа: M1=0 км/0 минут движения и нет рейса (`349–368,630–652`); совпавшие координаты не заменять фиктивными (`370–378`); fallback с коэффициентами показывать пунктиром и без манёвров (`322–346`); при нехватке GeoJSON не маркировать fallback как OSRM (`416–418`). Пошаговые инструкции, улицы, ETA, прогресс, перестроение, автомобиль и груз в архиве отсутствуют; это будущие функции, а не готовый навигатор. Trip оптимизирует порядок точек, но не учитывает вместимость и временные окна; для CVRP нужен отдельный решатель/алгоритм.

Проверки после разрешения разработки: M1, совпадающие/разные координаты, ошибочный OSRM, сохранённый дорожный маршрут, альтернативы и Table API при поддержке, геолокация только с согласия пользователя, независимость расчёта стоимости от происхождения линии.
